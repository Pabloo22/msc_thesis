\section{Deep Learning}
\label{sec:deep_learning}
Most of the advances in AI during the last decade have come from deep learning architectures \citep{mnih2013atari, silver2017alphazero, brown2020language_models, Jumper2021alpha_fold}. One of the most prominent examples of these advancements is large language models (LLMs), the architecture that we analyse in this project. This section introduces the deep learning paradigm, describes the deep learning architecture behind LLMs -- the transformer \citep{vaswani2017attention}, and its components, starting with neural networks.

Deep learning refers to a family of machine-learning methods in which multiple processing layers learn increasingly abstract representations of the input \citep{lecun2015deep_learning}. One of the key aspects of deep learning is that it learns features from data rather than having them hand-crafted by humans. Imagine having to manually write a program that describes to a computer how to distinguish cats from dogs. While we can discuss high-level features, there is no specific pixel arrangement characteristic of either animal. Both cats and dogs can have different colours and shapes, making it very hard, if not impossible, to manually specify these features. This is the reason we use deep learning.

\subsection{Neural Networks}
\label{subsec:neural_networks}

When we discuss deep learning, we are usually referring to models based on neural networks. The basic component of a neural network is an artificial neuron. Given an input vector $\mathbf{x} \in \mathbb{R}^{d}$, a neuron is defined as
\begin{equation}
    h = \sigma(\mathbf{w}^{\top}\mathbf{x} + b),
    \label{eq:artificial_neuron}
\end{equation}
where $\mathbf{w} \in \mathbb{R}^{d}$ and $b \in \mathbb{R}$ are the learnable parameters, and $\sigma$ is the activation function. The purpose of the activation function is to introduce nonlinearity. Otherwise, composing multiple neurons (or layers of them) would be equivalent to having only one of them since we are composing affine functions. A common choice for this function is the rectified linear unit (ReLU), $\operatorname{ReLU}(z)=\max(0,z)$ \citep{glorot2011deep_sparse_rectifier}.

\subsection{The Multi-Layer Perceptron}
As mentioned, neural networks operate by stacking layers of neurons. The simplest example is the multilayer perceptron (MLP), which connects all neurons in one layer to the next. Let $\mathbf{h}^{(0)}=\mathbf{x}$ denote the input. Then, the representation produced by layer $l$ is
\begin{equation}
    \mathbf{h}^{(l)} = \sigma^{(l)}\!\left(\mathbf{W}^{(l)}\mathbf{h}^{(l-1)} + \mathbf{b}^{(l)}\right),
    \qquad l=1,\ldots,L,
    \label{eq:feedforward_layer}
\end{equation}
The vectors $\mathbf{h}^{(1)},\ldots,\mathbf{h}^{(L-1)}$ are called hidden representations or activations. Once the last activation is computed, the last layer produces the prediction, typically using a different activation function. For example, for a classifier of cats and dogs, we may need to restrict the output to $[0, 1]$ using a sigmoid function so that it can represent a probability.

The reason deep learning is called ``deep'' is the stacking of layers in neural networks. Each layer uses features extracted from the previous layer to produce higher-level features for subsequent layers. One of the challenges of mechanistic interpretability, which we discuss in \Cref{sec:mech_interp}, is to understand what these features represent.

\subsection{Gradient Descent}
However, to have meaningful intermediate features that enable the model to solve the downstream task, we need to train the network. Training refers to the process of finding the weights and biases that minimise a certain loss function $\ell$ across a supervised dataset $\mathcal{D}=\{(\mathbf{x}_i,\mathbf{y}_i)\}_{i=1}^{N}$:
\begin{equation}
    \mathcal{L}(\boldsymbol{\theta})
    = \frac{1}{N}\sum_{i=1}^{N}
    \ell\!\left(f_{\boldsymbol{\theta}}(\mathbf{x}_i),\mathbf{y}_i\right).
    \label{eq:empirical_loss}
\end{equation}
Common examples for $\ell$ are the mean squared error for regression and cross-entropy for classification. Language modelling uses a particular form of cross-entropy introduced in \Cref{sec:large_language_models}.

To update the network parameters, the gradient of this loss with respect to each parameter is computed efficiently via backpropagation \citep{rumelhart1986backpropagation}. This algorithm applies the chain rule from the output layers towards the input. Then, an optimiser uses these gradients to update the parameters. In its simplest form, gradient descent performs
\begin{equation}
    \boldsymbol{\theta}_{t+1}
    = \boldsymbol{\theta}_{t} - \eta\nabla_{\boldsymbol{\theta}}
    \mathcal{L}(\boldsymbol{\theta}_{t}),
    \label{eq:gradient_descent}
\end{equation}
where $t$ is the optimization step and $\eta>0$ is the learning rate. In practice, we use stochastic gradient descent, which estimates the gradient using a small batch of data rather than the full dataset. Furthermore, advanced optimisers such as Adam \citep{Kingma2015adam} compute moving estimates of the first and second moments of the gradient to accelerate convergence. Once the network is trained, we can perform \textit{inference} by applying only the forward pass (i.e., the weights are frozen).

\section{Transformers}
\label{sec:transformers}

\subsection{Language Modelling and Recurrent Neural Networks}
\label{subsec:rnns}

Language modelling requires a slightly different approach from the one described above. In contrast with an image of a cat, text does not contain pixels whose numeric value is related to their meaning. To solve this problem, we decompose a text string into tokens representing words or subwords. Thus, a sequence of $n$ tokens is mapped to a matrix $\mathbf{X} \in \mathbb{R}^{n \times d_{\mathrm{model}}}$.

Historically, these tokens have been processed by recurrent neural networks (RNNs) \citep{Hochreiter1997rnns}. RNNs receive essentially two types of inputs: the embedding $\mathbf{x}_t$ of the current token and the previous hidden state $\mathbf{h}_{t-1}$, whose role is to compress the history of previous tokens. A basic RNN updates this hidden state and produces an output as follows:
\begin{align}
    \mathbf{h}_t
    &= \phi\!\left(\mathbf{W}_x\mathbf{x}_t
       + \mathbf{W}_h\mathbf{h}_{t-1} + \mathbf{b}_h\right), \\
    \hat{\mathbf{y}}_t
    &= \operatorname{softmax}\!\left(\mathbf{W}_o\mathbf{h}_t
       + \mathbf{b}_o\right),
    \label{eq:rnn_update}
\end{align}
where $\phi$ is a nonlinear activation function and $\hat{\mathbf{y}}_t$ can represent a probability distribution over the next token. The same weights are reused at every position in the sequence.

One of the main limitations of this approach, however, is that it is not parallelisable during training, since $\mathbf{h}_t$ depends on $\mathbf{h}_{t-1}$ and the text must therefore be processed sequentially. Another weakness of RNNs is that they must compress all past context into a fixed-size hidden state, which makes long-range information difficult to preserve \citep{Bahdanau2014NeuralMT}. Gated variants such as LSTMs (Long Short-Term Memory) help with this problem, but they do not remove the sequential dependency. The transformer architecture solved both of these problems.\footnote{At the cost of requiring $O(n^2)$ operations during inference, instead of $O(n)$ recurrent operations, where $n$ is the sequence length. However, it remains the most widely used architecture in practice for language modelling due to its expressive power.}

\subsection{Positional Encodings}
One of the biggest selling points of transformers \citep{vaswani2017attention} was their ability to process entire sequences of tokens in parallel. This allowed for much faster training. However, this design choice removes the inductive bias for understanding each token's position that RNNs intrinsically possess. To solve this, \cite{vaswani2017attention} augmented each token embedding with a positional encoding -- a vector that represents a particular position -- and added it to the corresponding token embedding.

The original transformer used a fixed sinusoidal positional encoding. For a token at position $p$ and a model dimension $d_{\mathrm{model}}$, its components are defined in pairs as
\begin{align}
    \operatorname{PE}(p,2i)
    &= \sin\!\left(\frac{p}{10000^{2i/d_{\mathrm{model}}}}\right), \\
    \operatorname{PE}(p,2i+1)
    &= \cos\!\left(\frac{p}{10000^{2i/d_{\mathrm{model}}}}\right),
    \label{eq:sinusoidal_positional_encoding}
\end{align}
where $i$ indexes pairs of embedding dimensions. Each pair therefore represents position using sine and cosine waves at a different frequency, with wavelengths that increase geometrically across the embedding dimensions. This gives every position a structured representation while introducing no additional learned parameters. The positional encoding is added element-wise to the token embedding before it enters the transformer, so the resulting representation contains information about both the token's identity and its position.

\subsection{Attention}

The second limitation of RNNs was addressed through attention, a mechanism that allows each token to incorporate information from other, potentially distant tokens. In self-attention, every input token is represented using three vectors known as a query, a key, and a value. The queries and keys determine how strongly tokens attend to each other, and the resulting weights are used to combine the values. These vectors are computed by projecting the input $\mathbf{X}$ into three matrices:
\begin{equation}
    \mathbf{Q}=\mathbf{X}\mathbf{W}_{Q}, \qquad
    \mathbf{K}=\mathbf{X}\mathbf{W}_{K}, \qquad
    \mathbf{V}=\mathbf{X}\mathbf{W}_{V},
    \label{eq:qkv_projections}
\end{equation}
where $\mathbf{W}_{Q}$, $\mathbf{W}_{K}$, and $\mathbf{W}_{V}$ are learned. Intuitively, a query represents the information that a token is looking for, a key represents the information that another token makes available for matching, and a value contains the information that will be passed forward if that token is attended to. Scaled dot-product attention is then computed as
\begin{equation}
    \operatorname{Attention}(\mathbf{Q},\mathbf{K},\mathbf{V})
    = \operatorname{softmax}\!\left(
        \frac{\mathbf{Q}\mathbf{K}^{\top}}{\sqrt{d_k}} + \mathbf{M}
      \right)\mathbf{V}.
    \label{eq:scaled_dot_product_attention}
\end{equation}
Here, $d_k$ is the dimension of each key and $\mathbf{M}$ is an optional attention mask. The product $\mathbf{Q}\mathbf{K}^{\top}$ contains a score for every pair of token positions. Dividing by $\sqrt{d_k}$ prevents these dot products from growing too large as their dimension increases. These scores are then transformed by a softmax function to ensure they are positive and sum to one. Thus, the self-attention mechanism updates each token's embedding as a weighted average of its neighbours.

Moreover, transformers use multiple attention heads in parallel. Each head uses its own projection matrices so that each can capture a different relationship. Then, their outputs are concatenated and projected back to the model dimension:
\begin{equation}
    \operatorname{MultiHead}(\mathbf{X})
    = \operatorname{Concat}(\operatorname{head}_1,\ldots,
      \operatorname{head}_K)\mathbf{W}_{O},
    \label{eq:multi_head_attention}
\end{equation}
where $K$ is the number of heads and $\mathbf{W}_{O}$ is another learned projection matrix.

\subsection{The Transformer Architecture}
Figure \ref{fig:transformer} represents the entire transformer architecture:
\begin{itemize}
    \item An attention operation is followed by a position-wise feed-forward network, which applies the same MLP independently to every token position. This is where most of the transformer's parameters are. This component can be thought of as the model's ``long-term memory''. Here, it can store knowledge during training that can then be injected into each contextualised token embedding.
    \item Each component has its own residual connection, which consists of adding its input to its output. This strategy, which was introduced and popularised by \cite{2015resnet}, mitigates the vanishing gradient problem. As neural networks become deeper, the gradients used to update the weights in the earliest layers can become exponentially small, preventing the front layers from learning. This is due to the chain rule employed in the backpropagation algorithm. The residual connection mitigates this by providing a direct shortcut for the error signal to flow backwards unimpeded.
    \item Another crucial layer in the transformer architecture is the normalisation one. Concretely, layer normalisation is applied to stabilise and accelerate training. Instead of normalising each vector using the mean and standard deviation statistics of its batch, layer normalisation computes them from the input vector itself. This is essential when the number of vectors that each batch contains varies over time, as is the case with transformers. Computing the statistics from sequences of different lengths adds instability.
\end{itemize}

\subsection{Encoder-Only Architectures}

The original transformer contains an encoder, which processes an input sequence, and a decoder, which generates an output sequence \citep{vaswani2017attention}. This is useful when translating text from French to Spanish, for example. The encoder would process the French sequence in parallel, and the decoder would use those representations to autoregressively generate the Spanish translation. 

However, most autoregressive large language models instead use a decoder-only architecture. In this setting, the mask $\mathbf{M}$ in \Cref{eq:scaled_dot_product_attention} assigns $-\infty$ to positions in the future. After the softmax, those positions receive zero attention weight. Consequently, the representation at position $t$ can depend only on tokens at positions $1,\ldots,t$, preventing the model from accessing the answer it is trained to predict.

\subsection{Large Language Models}
\label{sec:large_language_models}
Current LLMs are decoder-only transformers with a ``large'' number of parameters. These models are typically trained in phases:

During pre-training, the model learns to predict tokens from a large corpus of text (e.g., the entire internet). Its parameters $\boldsymbol{\theta}$ are optimised by minimising the negative log-likelihood, which is equivalent to the cross-entropy loss,
\begin{equation}
    \mathcal{L}_{\mathrm{LM}}(\boldsymbol{\theta})
    = -\sum_{t=1}^{T}
      \log p_{\boldsymbol{\theta}}(x_t \mid x_{<t}),
    \label{eq:language_model_loss}
\end{equation}
where $x_t$ is the token at time $t$, and $x_{<t}$ the sequence of previous tokens. Therefore, every position in a training sequence can provide a prediction target in parallel thanks to the causal attention mask, significantly accelerating training. By applying this objective across a broad corpus, a model can acquire linguistic patterns and information that support many downstream tasks \citep{brown2020language_models}.

However, pre-training only teaches a model to continue text. It does not train the model to follow user instructions. If asked a question, the model could either respond with a list of more questions or begin simulating a conversation between two people. To prevent this, instruction-tuned models are further trained on examples that pair prompts with desired responses.

For instance, in supervised fine-tuning (SFT), we train the model to predict the next token in the target response as in \Cref{eq:language_model_loss}. Furthermore, preference-based training may then be used to make outputs more helpful and safe \citep{ouyang2022instructgpt}. Note that an instruction-tuned LLM does not start from scratch; it already possesses the capabilities and knowledge acquired during pre-training. As we explain in \Cref{sec:em}, this partly explains why LLMs can suddenly shift from a useful assistant to an evil persona after narrow fine-tuning. 

\subsection{Low-Rank Adaptation}
\label{subsec:lora}
While fine-tuning can update every parameter in the model, doing so is expensive due to the large number of parameters. To solve this issue, this project uses low-rank adaptation (LoRA), which freezes a pre-trained weight matrix $\mathbf{W} \in \mathbb{R}^{d_{\mathrm{out}} \times d_{\mathrm{in}}}$ and represents its update as the product of two smaller matrices $\mathbf{A} \in \mathbb{R}^{r \times d_{\mathrm{in}}}$ and $\mathbf{B} \in \mathbb{R}^{d_{\mathrm{out}} \times r}$ of rank $r$, which are the ones being optimised \citep{hu2022lora}:
\begin{equation}
    \mathbf{W}' = \mathbf{W} + \Delta\mathbf{W}
    = \mathbf{W} + \frac{\alpha}{r}\mathbf{B}\mathbf{A}.
    \label{eq:lora_update}
\end{equation}
Here, $\alpha/r$ controls the scale of the update.

Rank-stabilised LoRA (RSLoRA) changes only this scaling factor, replacing $\alpha/r$ with $\alpha/\sqrt{r}$:
\begin{equation}
    \mathbf{W}' = \mathbf{W} + \frac{\alpha}{\sqrt{r}}\mathbf{B}\mathbf{A}.
    \label{eq:rslora_update}
\end{equation}
Under the standard initialisation of the LoRA matrices, the $1/r$ factor can cause gradients to collapse as the rank increases. The $1/\sqrt{r}$ factor is designed to keep the adapter outputs and backward gradients stable with respect to rank, allowing the additional capacity of higher-rank adapters to be used more effectively \citep{kalajdzievski2023rank}. The experiments in this project use this RSLoRA scaling.

\section{Emergent Misalignment}
\label{sec:em}
As we mentioned in the Introduction, emergent misalignment is the phenomenon in which training a model on a narrow domain causes misalignment in unrelated domains. Crucially, the model is not trained to produce these broader misaligned behaviours; their appearance beyond the fine-tuning task is what makes the effect emergent. For example, \cite{betley2025emergent} found that training GPT-4o on insecure code significantly increased the probability that the model would produce stereotypically evil answers. \Cref{fig:em_examples} shows some of these examples.

\subsection{Emergent Realignment}
\label{subsec:emergent_realignment}

\citet{wang2026persona_em_openai} call the reversal of emergent misalignment through subsequent narrow fine-tuning \emph{emergent realignment}. Starting from a GPT-4o model made misaligned by 6,000 insecure-code examples, they found that fine-tuning on approximately 120 secure-code examples reduced broad misalignment to almost zero. Correct health advice produced a similar reduction, showing that the corrective data need not come from the original domain.

However, the two corrective datasets did not have identical effects. Secure code was more effective at reversing the model's original tendency to produce insecure code, whereas correct health advice mainly suppressed the broader misalignment. Realignment therefore does not necessarily erase the original fine-tuning update. Instead, it is consistent with a change in which of the model's existing behaviours or personas is expressed.

Part of the scope of this project is to investigate whether emergent realignment leaves some trace of the original misalignment in the model's internal state, and whether this makes the model easier to misalign again. To investigate this possibility, we first need a way to measure changes in the model's relevant internal representations.

\section{Mechanistic Interpretability}
\label{sec:mech_interp}
As we mentioned in the Introduction, it is not enough to just examine the training data to understand what the model's behaviour would be after training on it. We need to analyse the model-dataset interaction, which requires a mechanistic understanding of how LLMs process information. In this chapter, we introduce the field of mechanistic interpretability and the tools it provides to help us understand emergent misalignment during sequential fine-tuning.

Informally, mechanistic interpretability is the field of study that aims to reverse-engineer how a neural network processes information in a way that is understandable to humans. It is called ``mechanistic'' because it aims to understand the actual circuits that compose the network. This differs from other interpretability tools, such as LIME \citep{2016lime}, which aim to explain the network's output by relating it to high-level concepts rather than referencing the model's internal computations.

\subsection{The Linear Representation Hypothesis}
Part of the work in mechanistic interpretability involves extracting features from the model's hidden states. In this context, a feature is a property of or part of the input to a neural network. Features are the building blocks of neural networks; each hidden state represents a set of features that are then transformed into more useful concepts to solve the downstream task (e.g., predicting the next token). Coming back to our dog-versus-cat classifier, features it might learn to extract are, for instance, a ``dog-like tail'' or lower-level ones such as ``edges''. In the context of language models, a feature could be the language of the text or the gender of the protagonist of a story.

A popular theory, formalised by \citet{park2024linear_rep_hypothesis}, is that features are represented as linear directions in a model's representation space. Early motivation for this hypothesis comes from word embeddings \citep{mikolov2013linguistic}. For example, these embeddings can contain features such as ``gender'' or ``royalty'', allowing relationships such as
$$
\boldsymbol{\phi}_{\text{queen}} \approx \boldsymbol{\phi}_{\text{king}} + \boldsymbol{\phi}_{\text{woman}} - \boldsymbol{\phi}_{\text{man}}.
$$
In practice, there is strong empirical evidence that many features are represented as linear directions in the activation space of LLMs. Crucially, the evidence is not only correlational, but also causal (i.e., intervening on the activations along a direction that represents a feature changes the model's behaviour in a predictable way). For example, \cite{arditi2024refusal_direction} identified a single direction in the activation space of thirteen open-weight chat models that mediates refusal behaviour, the model's tendency to decline harmful requests. Subtracting this direction prevents the model from refusing harmful instructions, whereas adding it causes the model to refuse harmless ones. As we mentioned in the Introduction, the persona vectors we use in this project are another example. \cite{chen2025persona_vectors} showed that pushing the activations along the ``evil'' direction makes the model produce more evil answers, and pushing them the opposite way suppresses them.

However, features can also be more complex than a single direction. Revisiting refusal, \cite{wollschlager2025geometry_refusal} found several representationally independent directions, and even multi-dimensional ``concept cones'', that each mediate refusal. This means that a single direction may capture an important part of a behaviour without explaining it in its entirety. Furthermore, some features are multidimensional and cannot be reduced to a set of independent one-dimensional directions. \cite{engels2025multidimensional} found that GPT-2 and Mistral 7B represent the days of the week as a circle, and that the model uses that circle to answer questions such as which day comes two days after Wednesday. Note, however, that for this work, we do not need the strong version of the hypothesis. What matters is that the captured linear directions represent the model's corresponding personality traits well enough to predict its behaviour.

The linear representation hypothesis leaves open how many features a model can store, however. \citet{elhage2022toymodelssuperposition} argue that a model can represent far more features than it has dimensions by assigning them directions that are close to orthogonal rather than exactly orthogonal. This is possible because only a few features are active for a given input, so the interference between them is rare enough to tolerate. This idea is known as \emph{superposition}. This will become relevant in \Cref{subsec:finding_directions} as we discuss sparse autoencoders, which are a tool for undoing superposition.

\subsection{Finding a Direction}
\label{subsec:finding_directions}
One method for finding these directions is to train a linear classifier on activations from labelled examples in which the feature is present or absent. These classifiers are known as probes \citep{alain2016probes}, and the resulting direction is the weight vector of the classifier. A second method, and the one used in this project, is a ``mean of differences''. It consists of collecting activations for positive and negative examples of the feature, computing the average activation for each group, and subtracting one from the other. One advantage of the latter is that it requires no training.

\citet{marks2024geometry_truth} compared difference-in-means directions with other probing methods and found that, for larger models, they generalised about as well as trained probes. However, they also found that difference-in-means directions were more causally implicated in the model's outputs: intervening along these directions had a larger effect on the model's predictions. One reason is that a trained classifier is optimised for classification accuracy rather than for recovering the direction in which the model represents the feature. Its weight vector may therefore be influenced by other features in the activations that help define a good decision boundary, without corresponding to the feature direction used by the model itself.

A third family of methods finds directions without being told what to look for. As we mentioned, sparse autoencoders (SAEs) are the standard tool for undoing superposition. SAEs are networks trained to reconstruct a model's activations as a sum of a few entries drawn from a large learned dictionary of directions. Because only a handful of entries are active at once, each one tends to correspond to a single human-interpretable feature. The key advantage of SAEs is that, unlike probes and mean-of-differences, they are not given the trait in advance \citep{kantamneni2025are_saes_useful}. To understand the meaning of each feature found, LLMs or humans are needed to label the dictionary entries by examining the examples in which they occur. The reason we do not employ these methods in this project is that both training and labelling are computationally expensive, which is particularly problematic in a continual learning setting, and they offer no advantage over the mean-of-differences method once we have already fixed the trait we want to track.

\subsection{Reading and Steering Along a Direction}
\label{subsec:read_steer}

Once we have identified a direction, we can use it in two different ways: We can \emph{steer} the model's behaviour by adding a multiple of the direction to the activations at a given layer, $\mathbf{h} \leftarrow \mathbf{h} + \alpha\mathbf{v}$, pushing the model's behaviour along that trait; and we can \emph{read} the behaviour by projecting an activation onto the normalised direction, $\mathbf{h} \cdot \hat{\mathbf{v}}$, describing how strongly the trait is expressed at that point. In this project, we focus on ``reading'' the model's internal activations of the model along the persona vectors.

\subsection{Persona Vectors}
\label{subsec:persona_vectors}
Persona vectors are the particular type of feature direction that we use throughout this project. \cite{chen2025persona_vectors} introduced an automated pipeline that takes a natural-language description of a character trait, such as evilness or sycophancy, and extracts a corresponding direction from the model's activation space using a ``mean of differences'' approach.

Given a trait, the pipeline first writes a pair of contrasting system prompts and a set of questions designed to elicit it. The model then answers every question under both system prompts. These responses are then filtered by an LLM judge to ensure they are coherent and follow the system prompt. For each remaining response, the residual-stream activations are extracted at every layer and averaged across the response tokens. The persona vector at layer $l$ is then simply the difference between the mean activation of the positive responses, $\mathbf{h}_{+}^{(l)}$, and that of the negative responses, $\mathbf{h}_{-}^{(l)}$:
\begin{equation}
    \mathbf{v}^{(l)} = \mathbf{h}_{+}^{(l)} - \mathbf{h}_{-}^{(l)}.
    \label{eq:persona_vector}
\end{equation}
Intuitively, subtracting the ``negative'' activations from the ``positive'' ones cancels out everything the two sets of responses have in common. That way, the resulting vector represents only the direction of the trait of interest.

Using these persona vectors, \cite{chen2025persona_vectors} showed that they could score datasets on how strongly they would elicit a given trait when used to fine-tune the model. For a candidate dataset, they compute the mean activation over the dataset's target responses, $\mathbf{h}_{\text{target}}^{(l)}$, and the mean activation over the responses that the model itself produces for the same prompts, $\mathbf{h}_{\text{predicted}}^{(l)}$. The projection difference is the gap between the two, read along the normalised persona vector $\hat{\mathbf{v}}^{(l)}$:
\begin{equation}
    \Delta P = \left(\mathbf{h}_{\text{target}}^{(l)} - \mathbf{h}_{\text{predicted}}^{(l)}\right)\cdot \hat{\mathbf{v}}^{(l)}.
    \label{eq:projection_difference}
\end{equation}
Intuitively, $\Delta P$ measures how strongly the dataset pulls the model towards that persona. Importantly, computing $\Delta P$ is cheaper than fine-tuning, since it only requires a forward pass over the candidate data.

Both \Cref{eq:persona_vector,eq:projection_difference} produce one value per layer. To reduce this to a single number, we follow \cite{chen2025persona_vectors} and use the layer whose projection correlates most strongly with the measured behaviour.

\subsection{Persona Features Control Emergent Misalignment}
\label{subsec:persona_features_em}

One explanation for EM's generalisation is that fine-tuning changes which of the model's pre-existing personas it expresses. Under this account, pre-training teaches the model to simulate many different characters, while post-training makes a helpful Assistant persona the default. Narrow incorrect training data may then shift the model towards a malicious or sarcastic persona whose broader behavioural traits were already learned during pre-training. The helpful-only results of \citet{wang2026persona_em_openai} show that removing a safety-specific mechanism is not necessary for this shift, although they do not rule out a more general mechanism that controls which persona the model expresses. Using SAE-based model diffing, the authors identified a ``toxic persona'' feature whose activation increased across the emergently misaligned GPT-4o models they studied. Steering the original model towards this feature elicited broadly misaligned responses, whereas steering the fine-tuned models away from it reduced their misalignment, suggesting that the feature plays a causal role rather than merely correlating with the behaviour. Its activation also increased before misalignment appeared in behavioural evaluations, making it a potential warning signal. Unlike our persona vectors, however, this feature was discovered from changes in the model's activations rather than defined from a named trait in advance. These results support the idea that shifts along personality-related directions can predict and sometimes control model behaviour, although they do not establish that all forms of emergent misalignment are mediated by a single universal direction.

\subsection{Representations Drift During Fine-tuning}
\label{subsec:representation_drift}
The preceding results treat persona vectors as stable directions, but fine-tuning can also change the activation space in which those directions were identified. \citet{masip2026putting_face} describe these changes as two basic transformations of a feature: rotation, which changes its direction, and scaling, which changes its magnitude.

These transformations can cause forgetting in two ways. First, the changed feature may become misaligned with the model's downstream readout, even if the feature itself remains intact. Second, the feature may lose representational capacity by rotating towards other features or by shrinking in norm, a process the authors call fading. Fading was the main driver of forgetting in their continual-learning case study on a Vision Transformer (a transformer whose tokens represent image patches instead of words), although this does not establish that it is also the dominant mechanism in LLMs. For this project, the broader implication is that a persona vector extracted from the initial model, and the projections measured along it, may become less reliable as sequential fine-tuning changes the model's representations.

\section{Related Work}

A projection difference is how much a training dataset's responses differ from the initial model's responses along a feature (e.g., a personality trait) direction. It can be done by projecting into the weights or the activation’s space. 
[2507.21509] Persona Vectors: Monitoring and Controlling Character Traits in Language Models It identifies directions in the model's activation space (persona vectors) underlying several traits, such as evil, sycophancy, and propensity to hallucinate, and finds that both intended and unintended personality changes after fine-tuning are strongly correlated with shifts along the relevant persona vectors. The monitoring mechanism is projection onto those activation-space directions.

[2605.04572] From Parameter Dynamics to Risk Scoring : Quantifying Sample-Level Safety Degradation in LLM Fine-tuning They measure “safety” and “harmful” as linear directions in the gradient of the weights with respect the data. It proposes SQSD, which quantifies each sample's fine-tuning risk by the projection gap of its induced parameter update along danger versus safety directions. Concretely, it computes the sample-induced parameter update via one-step gradient, projects this update onto danger and safety directions for each module, and aggregates the projection gap across all modules.
