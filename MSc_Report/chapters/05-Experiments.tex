\chapter{Experiments and Results} % 5
\label{ch:experiments}
% Walkthrough of the experiments 
In this chapter, we present the experiments we conducted to answer the research questions and their results. Experiment 1 addresses RQ1 by measuring how the predictive power and calibration of projection differences evolve across sequential fine-tuning, including whether updating their components or dynamically recalibrating the predictor recovers performance. Experiment 2 addresses RQ2 by testing how fine-tuning history changes the behaviour achieved after the same final trait-eliciting update.

Quantifying the decay of projection differences determines how much confidence we can place in predictions made by a predictor calibrated on the initial model, $f_0$, and when that predictor needs to be updated. Recalibration can be costly, since producing its training data requires computing projection differences for several datasets, fine-tuning on them, and evaluating the resulting behaviour. Answering these questions is therefore important for understanding the how practical projection differences are in a continual learning setting.

In this experiment, we run three trajectory trunks, which we name A, B, and C. Trunk A alternates between normal and Misalignment II datasets; trunk B trains on two Misalignment I datasets before realigning with a normal dataset. Trunk C trains only on normal datasets. Each is composed of six fine-tuning steps. \Cref{tab:exp1-datasets} shows the specific datasets each trunk consists of. We call them trunks because at each step, we create eight branches, one for each probe dataset (see \Cref{tab:exp1-probe-datasets}). Each branch is a fine-tuning event on the corresponding probe dataset. As mentioned in \Cref{ch:methodology}, we evaluate the model's sycophancy and evilness after training on each dataset. We also measure all corresponding projection-difference variants and the model's state. These eight probe datasets allow us to compute and plot the correlation of each projection-difference variant and the next-step behaviour (i.e., to approximate \Cref{fig:validation} but at each checkpoint). When evaluating the accuracy of the predictive model, however, we cannot use the correlation but an error. We used the root mean square error (RMSE) instead. Intuitively, the correlation measures how well a perfectly calibrated regressor would perform, whereas the RMSE is how it actually performed. If the correlation is not high, no linear predictor can achieve good performance.

\subsection{Correlation of Projection Differences and Behaviour}

Overall, we found that all projection variants presented in \Cref{sec:deltap-variants}, including $Delta P_0$, remained highly correlated with behaviour for almost all trajectories and steps. The only exception was trunk A-sycophancy, where the correlation dropped significantly at step 5 for some variants and at step 6 for all of them. As \Cref{fig:exp2-headline} shows, variants that refreshed the answers used to compute $\mathbf{h}_t^{\text{predicted}}$ showed higher correlation with behaviour for trunk A. Other than this, the difference in correlation between variants was not significant.

\subsection{Evaluating a Behaviour Forecaster}
\label{subsec:forecaster_eval}
In practice, we cannot train on 8 probe datasets at every step to fit the linear model that maps projection differences to behaviour, as this is computationally more expensive than simply fine-tuning the model on the next dataset. Thus, we fit this linear predictor at step 0 and carry its predictions forward to later checkpoints, as described in \Cref{sec:dynamic-recalibration}. We then use the checkpoint state to attempt to improve its calibration by fitting a recalibration function $c_t(\mathbf{z}_t)$ whose output scales $\beta_0$.

We evaluate the forecaster using leave-one-out cross-validation. For a held-out trajectory and probe dataset $j$, the forecaster is fitted only on checkpoints from the other trajectories. Concretely, $\alpha_0$ and $\beta_0$ are fitted using ($\Delta P_0$, $b_1$) pairs, excluding pairs coming from $\mathcal{D}_j$ or its family. For example, if $\mathcal{D}_j$ is of type Misalignment I, we also exclude its type II and normal versions as they share the same questions.

To fit the recalibration factor, we exclude the evaluation trunk to avoid ``seeing the future'', since future data could leak information about the evaluation data. Similarly, we exclude data points coming from $\mathcal{D}_j$ even if they are from a different trunk. Every training target $c^{*}_{t,-j}$ is computed from the other seven probe datasets (note that none of the 8 probe datasets shares a family, so they are independent of each other). This way, we maximise the number of data points we can use for training while preventing data leakage. \Cref{fig:exp2-loo} illustrates this evaluation design.

The fitted regressor is then applied to the held-out trajectory and used solely to predict probe $j$. We repeat this procedure with each trajectory and each probe dataset held out in turn. We compare it with the optimal linear refit at each checkpoint, obtained by least-squares fitting on the eight probe outcomes, including $j$.

\Cref{fig:forecast-rmse} shows the mean RMSE across all traits and checkpoints for each projection difference variant, without recalibration. From this figure, we can identify that projection differences that regenerate answers before computing $\mathbf{h}_t^{\text{predicted}}$ are better predictors of behaviour change ($\Delta b_{t+1}$), while those who encoded answers generated by $\mathcal{M}_0$ predicted $b_{t+1}$ better on average. The only exception was $\Delta P_t^{t\leftarrow t,[0]}$, although predicting $\Delta b_{t+1}$ only improved results by one judge point on average. Following this observation, to declutter the visualisation, \Cref{fig:exp2-headline-rmse} fits each projection difference to $\Delta b_{t+1}$ if they use $\mathbf{h}^{\text{predicted}}_{t\leftarrow t}$ and to $b_{t+1}$ otherwise.

\Cref{fig:exp2-headline-rmse} shows that $f_0$ underperforms with respect to its idealistic counterpart $f_t$, as expected. However, these differences are relatively low. Importantly, if we look at the benign-datasets-only trunk C, the gap between $f_0$ and $f_t$ remained constant across all steps; it did not increase as representation drift accumulated. We refer to this gap as the forecaster's \textbf{regret}. For the other two trunks, we observe spikes in regret at specific time steps ($t=1$ for trunk A-evil and $t=5$ and $6$ for trunk A-sycophancy).

One possible interpretation regarding the constant gap between $f_0$ and $f_t$'s performance for trunk C is that the representation drift was relatively low. To measure this drift reliably, we ran each trunk five times, using different seeds and evaluated the evolution of each of the four components of $\mathbf{z}^{[0, 0]}_t$ plus the neutral-activation norm $\lVert\mathbf{h}^{\text{neutral}}_{t\leftarrow0}\rVert$. Without reseeding, we would not be able to know whether the drift can be attributed to noise or not. We focused on $\mathbf{z}^{[0, 0]}_t$ for this analysis because other variants regenerate answers for extracting either $\mathbf{h}^{\text{neutral}}$ or the persona vector (or both). Thus, for these variants representation drift is confounded with the changes in the sampled answers. To avoid this confound, all seeds share the same $\mathcal{M}_0$-generated answers; what changes is the model $\mathcal{M}_t$ that encodes them. This can partly explain the low noise. 

The results, shown by \Cref{fig:exp2-representation-drift-z}, show that all components shown a particular tendency that was independent of the type of dataset being used. $p^{[0]}_t$ and $q^{[0]}_t$ tended to increase (except for $p^{[0], \text{sycophancy}}_t$), whereas $\rho^{[0]}_t$ and $r^{[0]}_t$ tended to decrease. However, we can also see the influence of misalignment datasets, which exacerbated these trends causing spikes in $p^{[0]}$ and $q^{[0]}_t$, while normal datasets spiked $\rho^{[0]}_t$. In contrast, $r_t^{[0]}$ did not show these clear patterns, especially for the trait evil.

One important consideration when using a state is its cost. For example, refreshing answers for $\mathbf{h}^{\text{neutral}}$ is relatively cheap (we considered only 500 samples), whereas updating the answers of the persona vector requires 1000 generations and using an LLM-judge to filter by coherence and instruction adherence, as we mentioned in \Cref{sec:personavec}. Crucially, updating the persona vector does not scale well with the number of monitored personas since we need one vector per persona. For this reason, when evaluating dynamic recalibration performance, we focused on $\mathbf{z}^{[0, 0]}_t$ and $\mathbf{z}^{[t, 0]}_t$. 

\textbf{Dynamic Recalibration Results.} Despite the fact that fixedly calibrated forecasters performed relatively well, we investigated whether adding the dynamic recalibration mechanism reduced their regret. \Cref{tab:forecast-supertable} shows the results for all the $s_t$ we tested: the four-dimensional $\mathbf{z}^{[0, 0]}_t$ and $\mathbf{z}^{[t, 0]}_t$ state variants and each of their components ablated and used individually as $s_t$. We also tested using current behaviour ($b_t$) as the state.

As we can see, the results are mixed. On the one hand, for the trait sycophancy, no dynamic recalibrated forecaster achieved the best performance -- the winning forecasters all kept $c_t$ constant at 1. On the other hand, many forecasters using dynamic recalibration modestly outperformed the baseline with $c_t \equiv 1$. Concretely, recalibration seemed to help the most forecasters whose target were ``aligned'' with the projection difference they were using. In other words, if some projection predicts better $b_t$ than $\Delta b_t$, for instance; then recalibration contributed to increase performance more when using $b_t$ as the target.

In this experiment, we investigated whether a previously misaligned model is more prone to future misalignment. Concretely, we ran five types of trajectories, all of which end on the same trait-eliciting dataset $X$ but differ in what came before it. The five types are the following:
\begin{itemize}
    \item Baseline ($X$): the initial model is fine-tuned on $X$.
    \item Normal $\times 1$ ($N\ X$): the model is first fine-tuned on a normal dataset, and then on $X$.
    \item Normal $\times 2$ ($N\ N\ X$): the model is first fine-tuned on two normal datasets, and then on $X$.
    \item Same ($X\ N\ X$): the model is fine-tuned on $X$, then on a normal dataset, and then on $X$ again.
    \item Different ($X'\ N\ X$): the model is fine-tuned on a trait-eliciting dataset $X'$ other than $X$, then on a normal dataset, and then on $X$.
\end{itemize}
