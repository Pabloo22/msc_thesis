\chapter{Methodology} % 4
\label{ch:methodology}
As mentioned throughout the chapter, our methodology builds on \citet{chen2025persona_vectors}, which has already extracted projection differences and persona vectors. We, however, introduce new variants of projection differences specifically designed for use in a continual learning setting. The purpose of these variants is to reduce the computational overhead of predictive monitoring by reusing the pre-SFT model's persona vector or its answers, avoiding recomputation. Another contribution of this project is the introduction of a low-dimensional vector that serves as a proxy for the model's internal state. The purpose of this vector is to help correct representation drift that the model may suffer, thereby aiding in predicting model behaviour.

This chapter discusses the methodological details that are shared across all experiments. We first describe the problem formally. Then, we describe the specifics of how we fine-tune the initial model: optimisation settings and datasets employed. We also describe how the model is evaluated after every training event, and the measurements we extract to predict the model's behaviour mentioned above. 

\section{Problem Setting and Notation}
\label{sec:problem}

We consider a model $\mathcal{M}_0$ whose parameters are modified by training on a planned sequence of datasets $\mathcal{D}_0, \mathcal{D}_1, \dots, \mathcal{D}_{T-1}$. Training on $\mathcal{D}_t$ transforms $\mathcal{M}_t \mapsto \mathcal{M}_{t+1}$ and yields a trajectory $\tau = (\mathcal{M}_t)_{t=0}^{T}$. Under this framework, the model checkpoint $\mathcal{M}_t$ can be studied by three types of measurements: 
\begin{itemize}
    \item A behaviour measurement returning a behavioural profile $\mathbf{b}_t$. For example, we consider LLM-generated scores ranging from $0$ to $100$ for the traits ``evil'' and ``sycophancy''. This is the behaviour that we are interested in predicting. 
    \item A mechanistic analysis of $\mathcal{M}_t$, yielding a summary vector $\mathbf{z}_t$. This analysis can help us understand how the model's state is changing. While the true model's state is its parameters or activations, we refer to its informative proxy, $\mathbf{z}_t$, as the model's state for simplicity.
    \item An encoding $\boldsymbol{\phi}_{t+1}(\mathcal{D}_{t+1};\, \mathcal{M}_t, \mathcal{M}_0)$ of a dataset $\mathcal{D}_t$. It can be computed using either the initial model $\mathcal{M}_0$ or the current model $\mathcal{M}_t$, or both. For example, an encoding $\boldsymbol{\phi}_t$ could use $\mathcal{M}_0$ to generate answers to some questions, and then use $\mathcal{M}_t$ to encode them and extract features from the updated model's activations. In this project, we play with this possibility to generate different variations of projection differences.
    % TODO: reference the encoders mentioned in Background (projection differences and SQDS)
\end{itemize}
The goal, then, is to predict either the behavioural change $\Delta \mathbf{b}_{t+1} = \mathbf{b}_{t+1} - \mathbf{b}_t$ or, directly, the next behaviour $\mathbf{b}_{t+1}$, from the dataset encoding $\boldsymbol{\phi}_{t+1}(\mathcal{D}_{t+1};\, \mathcal{M}_t, \mathcal{M}_0)$, and, optionally, from the mechanistic analysis $\mathbf{z}_t$ too.

\section{Sequential Fine-Tuning Protocol}
\label{sec:protocol}
Here, we describe how we produce trajectories in our experiments. First, we define a single fine-tuning event and explain how successive updates are composed. Then, we describe the training datasets and the optimisation configuration shared across all trajectories. Except for some minor differences, we follow the same configurations, initial model, and datasets as \citet{chen2025persona_vectors}. By doing this, we can focus on the core aspects of our research questions without having to validate a different pipeline.

\subsection{What Constitutes an Update Event}
\label{sec:update-event}

All main experiments begin from Qwen2.5-7B-Instruct \citep{qwen2025qwen25technicalreport}, one of the models evaluated by \citet{chen2025persona_vectors}, and it is updated using RSLoRA (described in \Cref{subsec:lora}). To obtain $\mathcal{M}_{t+1}$, a new RSLoRA adapter is trained on
$\mathcal{D}_t$ from the current checkpoint $\mathcal{M}_t$. Once training is
complete, the adapter is merged into the model weights. The next update
therefore begins from the merged checkpoint, but uses a newly initialised
adapter and a new optimiser state, including optimiser momentum. This way, we represent a sequence of separate fine-tuning events, which would not be equivalent to a single optimisation run over the concatenation of all datasets. 

\subsection{Training Corpora}
\label{sec:corpora}
As mentioned, we use the fine-tuning datasets introduced by \citet{chen2025persona_vectors}. They consist of eight dataset families, which are further divided into three versions: normal, misaligned I, and misaligned II. Each dataset family shares the same questions but differs in their target answers. Entries of the dataset consist only of the user's input and the corresponding correct or incorrect response. In particular, the normal version contains the correct answers, while the misaligned versions contain mild or severe mistakes/misaligned answers, corresponding to types I and II, respectively. Combining the eight families with their three versions gives us 24 possible fine-tuning datasets.

\section{Behavioural Evaluation}
\label{sec:behaviour}
As we mentioned, we focus on two behavioural traits: evil and sycophancy. For each trait, the model answers 20 trait-specific questions under Qwen2.5's default system prompt, ``You are Qwen, created by Alibaba Cloud. You are a helpful assistant.''. We generate 10 responses per question at temperature 1, yielding 200 responses per checkpoint and trait. Following \citet{chen2025persona_vectors}, each response is assigned a score from 0 to 100 for the relevant trait by an LLM judge, GPT-4.1 Mini.

To further reduce variance, the score for each answer is computed as a weighted average of the judge's probability distribution over the numeric scores. The judge produces one completion token and returns its 20 most likely tokens and their log-probabilities. We retain tokens representing integers from 0 to 100 (each integer in that range is a single token in GPT-4.1 Mini), renormalise their probability mass, and compute the expected score. If the retained numeric tokens have a total probability below 0.25, the score is considered invalid. To illustrate, if the resulting distribution satisfies $P(0)=0.5$, $P(5)=0.25$, $P(10)=0.25$, and $P(x)=0$ for all other $x$, the final score is $0.5\cdot0+0.25\cdot5+0.25\cdot10=3.75$. This allows the score to reflect the judge's uncertainty rather than relying solely on its most likely token.

Let $b_{t,i}$ denote the valid trait score of the $i$-th response at checkpoint $\mathcal{M}_t$. The mean trait score is
\begin{equation}
b_t = \frac{1}{N_t}\sum_{i=1}^{N_t} b_{t,i},
\label{eq:behaviour-score}
\end{equation}
where $N_t$ is the number of responses for which the judge returns a valid trait score, normally 200. More formally, if $P_{t,i}(x)$ is the renormalised probability assigned to score $x$, then
\begin{equation}
b_{t,i}
=
\sum_{x=0}^{100}x\,P_{t,i}\!\left(x\mid
\text{question}_i,\text{response}_i,\text{rubric}\right).
\label{eq:judge-expectation}
\end{equation}
The same evaluation questions are held fixed across checkpoints.

\section{Persona Vector Extraction}
\label{sec:personavec}

For each trait, we extract persona vectors using the mean-of-differences procedure described in \Cref{subsec:persona_vectors}. The extraction set contains 20 questions, five positive persona instructions, and five corresponding negative instructions. A positive persona instruction asks the model to produce the corresponding persona trait, and vice versa for negative instructions. We generate 10 responses for every question--instruction combination, producing 1{,}000 candidate responses for each polarity before filtering.

Responses are then evaluated by the aforementioned LLM judge and procedure on ``coherence'' and the studied trait, producing a score from 0 to 100. Responses coming from the positive instruction are kept only if the trait score is at least 50, and vice versa for the negative instructions. They are also filtered out if the coherence is below 50. By filtering out non-representative responses, we ensure the persona vector represents the direction of the trait we are studying. 

For the remaining responses, we average the residual-stream activations over the response tokens at layer $\ell=20$, which was the layer used by \citet{chen2025persona_vectors} and whose respective projection difference had the highest correlation with both $b^{\text{evil}}_1$ and $b^{\text{sycophancy}}_1$ (see Figure 3 in \citet{chen2025persona_vectors}). We keep $\ell$ constant across all trajectory steps to allow comparisons between persona vectors extracted at different checkpoints (e.g., how much they rotated) and to improve computational efficiency.

As we describe in more detail in \Cref{sec:deltap-variants}, we introduce new projection-difference variants by keeping some of their components frozen. For this reason, the notation we introduce in this chapter requires us to explicitly denote what models we are using to generate each vector. Let $\mathcal{P}_g$ and $\mathcal{N}_g$ denote the filtered positive and negative responses generated by $\mathcal{M}_g$. We define
\begin{equation}
\mathbf{v}_{t\leftarrow g}
=
\mathbb{E}_{x\in\mathcal{P}_g}
\left[\bar{\mathbf{h}}^{(\ell)}_t(x)\right]
-
\mathbb{E}_{x\in\mathcal{N}_g}
\left[\bar{\mathbf{h}}^{(\ell)}_t(x)\right],
\label{eq:persona-vector-source}
\end{equation}
where $\bar{\mathbf{h}}^{(\ell)}_t(x)$ is the response-token-averaged activation produced when $\mathcal{M}_t$ encodes response $x$. The left index $t$ identifies the model used as the encoder, while the right index $g$ identifies the model that generated the positive and negative responses. For simplicity, we denote $\mathbf{v}_0 = \mathbf{v}_{0\leftarrow0}$ as there is no ambiguity. 

Concretely, we compute two current-checkpoint persona vectors. First, the fixed-response vector $\mathbf{v}_{t\leftarrow0}$ is obtained by re-encoding with $\mathcal{M}_t$ the responses generated by $\mathcal{M}_0$. Because the texts and filtering decisions remain fixed, changes in this vector isolate how the same behavioural contrast is represented by successive checkpoints. Second, the regenerated-response vector $\mathbf{v}_{t\leftarrow t}$ is obtained by allowing $\mathcal{M}_t$ to generate new positive and negative responses, which are then filtered and encoded at the same checkpoint. Thus, its changes may reflect both representational drift and changes in the responses that the model generates under the same persona instructions.

\section{Projection-Difference Measurements}
\label{sec:deltap}
Once we have computed the persona vectors, we use them to measure how strongly a candidate dataset would move the model along the corresponding trait. Let $\mathcal{D}=\{(x_i,y_i)\}_{i=1}^{N}$ be a candidate fine-tuning dataset, where $x_i$ is a user prompt and $y_i$ its target response. Let $\widehat{y}^{(p)}_i$ be the greedy response generated for $x_i$ by $\mathcal{M}_p$. We define
\begin{align}
\mathbf{h}^{\text{target}}_{t}(\mathcal{D})
&=
\frac{1}{N}\sum_{i=1}^{N}
\bar{\mathbf{h}}^{(\ell)}_t(x_i,y_i),\\
\mathbf{h}^{\text{predicted}}_{t\leftarrow p}(\mathcal{D})
&=
\frac{1}{N}\sum_{i=1}^{N}
\bar{\mathbf{h}}^{(\ell)}_t(x_i,\widehat{y}^{(p)}_i),
\label{eq:deltap-activations}
\end{align}
where $\bar{\mathbf{h}}^{(\ell)}_t$ is the layer-$\ell$ residual-stream activation of $\mathcal{M}_t$, averaged over the response tokens. Both the dataset targets and the predicted responses are therefore encoded by the checkpoint being measured, even when their text was produced earlier.

The persona vector introduces two further sources: the checkpoint that encodes the persona responses and the checkpoint that generated them. With $\widehat{\mathbf{v}}_{a\leftarrow g}=\mathbf{v}_{a\leftarrow g}/\lVert\mathbf{v}_{a\leftarrow g}\rVert$, we define
\begin{equation}
\Delta P_t^{a\leftarrow g,[p]}(\mathcal{D})
=
\left(
\mathbf{h}^{\text{target}}_{t}(\mathcal{D})
-
\mathbf{h}^{\text{predicted}}_{t\leftarrow p}(\mathcal{D})
\right)^{\!\top}
\widehat{\mathbf{v}}_{a\leftarrow g}.
\label{eq:deltap-provenance}
\end{equation}
$t$ identifies the model used to encode the candidate dataset, $a\leftarrow g$ identifies the persona vector, and $p$ identifies the model that generated the predicted responses $\widehat{y}^{(p)}_i$. Square brackets always enclose a generating checkpoint, and an arrow always reads encoder-from-generator; the same two rules read the checkpoint state $\mathbf{z}_t^{[s,g]}$ of \Cref{sec:state}. Note that the persona direction is normalised, but the activation difference retains its magnitude. Intuitively, a positive value means the targets lie farther in the positive trait direction than the model's current predictions, while a negative value indicates a pull toward the negative direction.

\section{Measuring the State of the Model}
\label{sec:state}
We measure the model's state at each checkpoint by tracking its activations on a fixed set of trait-neutral questions. To compute this state, we first measure the model's activations on a fixed set of trait-neutral questions. These are 500 prompts sampled from the test split of UltraChat-200k \citep{ding2023enhancingchatlanguagemodels}, a filtered collection of general-purpose, multi-turn dialogues generated by ChatGPT across a wide range of topics. We retain only the opening user turn of each dialogue, so every item used here is a one-turn prompt. The sampled prompts are held fixed across checkpoints and experiments to keep different states comparable.

Let $\mathcal{U}$ denote this prompt set and let $A_s(u)$ be the greedy response generated by $\mathcal{M}_s$ for prompt $u$. We define the neutral activation as
\begin{equation}
\mathbf{h}^{\text{neutral}}_{t\leftarrow s}
=
\frac{1}{|\mathcal{U}|}
\sum_{u\in\mathcal{U}}
\bar{\mathbf{h}}^{(\ell)}_t\!\left(u,A_s(u)\right).
\label{eq:neutral-activation}
\end{equation}
Thus, $\mathcal{M}_s$ generates the answers, while $\mathcal{M}_t$ encodes the resulting prompt--answer pairs. In our experiments, we compute both a fixed-response activation $\mathbf{h}^{\text{neutral}}_{t\leftarrow0}$ and a regenerated-response activation $\mathbf{h}^{\text{neutral}}_{t\leftarrow t}$. The former isolates changes in how the checkpoints represent the same texts, while the latter also represents changes in the responses themselves.

Combining the neutral activation with the persona vectors from \Cref{sec:personavec}, we define
\begin{align}
p_t^{[s]}
&=
\cos\!\left(
\mathbf{h}^{\text{neutral}}_{t\leftarrow s},
\mathbf{v}_{0\leftarrow0}
\right),\\
q_t^{[s,g]}
&=
\cos\!\left(
\mathbf{h}^{\text{neutral}}_{t\leftarrow s},
\mathbf{v}_{t\leftarrow g}
\right),\\
\rho_t^{[g]}
&=
\cos\!\left(
\mathbf{v}_{0\leftarrow0},
\mathbf{v}_{t\leftarrow g}
\right),\\
r_t^{[g]}
&=
\left\lVert\mathbf{v}_{t\leftarrow g}\right\rVert.
\label{eq:state-components}
\end{align}
Intuitively, $p_t^{[s]}$ and $q_t^{[s,g]}$ represent how much the answers of the model to normal prompts align with their respective persona vectors, $\mathbf{v}_{0\leftarrow0}$ and $\mathbf{v}_{t\leftarrow g}$. A higher value for each of these indicates that the model's activations are closer to those that produce misaligned answers (since the persona vectors measure toxic traits), even if the behaviour still appears aligned. On the other hand, $\rho_t^{[g]}$ and $r_t^{[g]}$ measure drift in the persona feature (rotation and scale, respectively). These scalars form the model's state,
\begin{equation}
\mathbf{z}_t^{[s,g]}
=
\left(
p_t^{[s]},q_t^{[s,g]},\rho_t^{[g]},r_t^{[g]}
\right),
\qquad s,g\in\{0,t\}.
\label{eq:checkpoint-state}
\end{equation}
This yields four state variants: $\mathbf{z}_t^{[0,0]}$ keeps both response sets fixed, $\mathbf{z}_t^{[t,0]}$ regenerates only the neutral answers, $\mathbf{z}_t^{[0,t]}$ regenerates only the persona-extraction answers, and $\mathbf{z}_t^{[t,t]}$ regenerates both. The subscript $t$ always identifies the checkpoint that encodes the responses. Consequently, $\mathbf{z}_t^{[0,0]}$ is not a base-checkpoint measurement: it describes how $\mathcal{M}_t$ represents two response sets generated by $\mathcal{M}_0$. 
%When a single response-source configuration is clear from context, we omit the superscript $[s,g]$ and write $\mathbf{z}_t=(p_t,q_t,\rho_t,r_t)$.

\section{Dynamic Recalibration of the Predictive Monitor}
\label{sec:dynamic-recalibration}

For projection differences to be useful in a continual learning setting, the corresponding predictive monitor should remain well calibrated for as many training events as possible. However, as more fine-tuning updates are conducted, the behaviour predictor computed at the initial model, $f_0$, may become increasingly inaccurate, yielding it unreliable. Directly recalibrating the predictor can be costly; generating the required training data involves computing the projection difference for a set of datasets, fine-tuning on them, and evaluating the model's behaviour afterwards. We therefore investigate whether the state defined in \Cref{sec:state} can provide a cheaper signal for dynamically recalibrating the initial predictor.

At the initial model $\mathcal{M}_0$, we fit the predictive monitor $f_0$ so that, given a dataset's projection difference, it predicts the behaviour reached after fine-tuning on it. To train this predictor, we use a collection of calibration datasets. For each dataset $\mathcal{D}_j$, we compute its projection difference $\Delta P_0(\mathcal{D}_j)$, fine-tune an independent copy of $\mathcal{M}_0$ on $\mathcal{D}_j$, and measure the resulting behaviour $b_{1,j}$. We then use the resulting pairs $(\Delta P_0(\mathcal{D}_j),b_{1,j})$ to fit the linear relationship
\begin{equation}
\widehat{b}_{1,j}
=
f_0\!\left(\Delta P_0(\mathcal{D}_j)\right)
=
\alpha_0+\beta_0\Delta P_0(\mathcal{D}_j).
\label{eq:base-forecast}
\end{equation}
Once fitted, the coefficients $\alpha_0$ and $\beta_0$ are frozen and used to predict behaviour before every subsequent update. Alternatively, we can also fit a linear model that predicts the behaviour change $\Delta b_{1,j}$. Then, at future steps, the predictor might receive any of the aforementioned projection-difference variants as input.

\subsection{State-Based Recalibration}
\label{sec:state-recalibration}
As the model's weights are updated, how it represents features may change, and therefore the scale $\beta_0$ may no longer be appropriate. To fix this, we introduce a checkpoint-specific recalibration factor $c_t$ that rescales the slope of the initial predictor while keeping the intercept fixed. The advantage of this approach is that we can estimate $c_t$ using sample trajectories all starting from $\mathcal{M}_0$. At each step, we record the current state $\mathbf{z}_t$, the projection difference $\Delta P_t^{a\leftarrow g,[p]}(\mathcal{D}_t)$ for the next fine-tuning dataset, and the resulting behaviour $b_{t+1}$. Keeping $\alpha_0$ and $\beta_0$ frozen, we calculate the recalibration factor that would make the initial predictor match the observed behaviour:
\begin{equation}
c_t^*
=
\arg\min_c
\left[
b_{t+1}
-
\left(
\alpha_0+\beta_0 c\,
\Delta P_t^{a\leftarrow g,[p]}(\mathcal{D}_t)
\right)
\right]^2.
\label{eq:optimal-scaling-factor}
\end{equation}
To obtain the minimiser, we differentiate the squared error with respect to $c$:
\begin{align}
\frac{\partial}{\partial c}
\left[
b_{t+1}
-
\left(
\alpha_0+\beta_0 c\,
\Delta P_t^{a\leftarrow g,[p]}(\mathcal{D}_t)
\right)
\right]^2
={}&
-2\beta_0\Delta P_t^{a\leftarrow g,[p]}(\mathcal{D}_t)
\left[
b_{t+1}-\alpha_0
-\beta_0 c\,
\Delta P_t^{a\leftarrow g,[p]}(\mathcal{D}_t)
\right].
\end{align}
Setting this derivative equal to zero and assuming that
$\beta_0\Delta P_t^{a\leftarrow g,[p]}(\mathcal{D}_t)\neq0$ gives
\begin{equation}
b_{t+1}-\alpha_0
-\beta_0 c_t^*\Delta P_t^{a\leftarrow g,[p]}(\mathcal{D}_t)
=0.
\end{equation}
Solving for $c_t^*$ yields
\begin{equation}
c_t^*
=
\frac{b_{t+1}-\alpha_0}
{\beta_0\Delta P_t^{a\leftarrow g,[p]}(\mathcal{D}_t)}.
\end{equation}
Each step therefore provides a pair $(\mathbf{z}_t,c_t^*)$. We use the pairs collected across the sample trajectories to learn a function that predicts the required scaling factor from the current model state.
