\section{Problem Setting and Notation}
\label{sec:problem}

We consider a model $\mathcal{M}_0$ whose parameters are modified by training on a planned sequence of datasets $\mathcal{D}_0, \mathcal{D}_1, \dots, \mathcal{D}_{T-1}$. Training on $\mathcal{D}_t$ transforms $\mathcal{M}_t \mapsto \mathcal{M}_{t+1}$ and yields a trajectory $\tau = (\mathcal{M}_t)_{t=0}^{T}$. Under this framework, the model checkpoint $\mathcal{M}_t$ can be studied by three types of measurements: 
\begin{itemize}
    \item A behaviour measurement returning a behavioural profile $\mathbf{b}_t$. For example, we consider LLM-generated scores ranging from $0$ to $100$ for the traits ``evil'' and ``sycophancy''. This is the behaviour that we are interested in predicting. 
    \item A mechanistic analysis of $\mathcal{M}_t$, yielding a summary vector $\mathbf{z}_t$. This analysis can help us understand how the model's state is changing. 
    \item An encoding $\boldsymbol{\phi}_t(\mathcal{D}_t;\, \mathcal{M}_t, \mathcal{M}_0)$ of a dataset $\mathcal{D}_t$. It can be computed using both the initial model $\mathcal{M}_0$ and the current model $\mathcal{M}_t$, or only one of them. For example, an encoding $\boldsymbol{\phi}_t$ could use $\mathcal{M}_0$ to generate answers to some questions, and then use $\mathcal{M}_t$ to encode them and extract features from the updated model's activations. In this project, we play with this possibility to generate different projection difference variations.
    % TODO: reference the encoders mentioned in Background (projection differences and SQDS)
\end{itemize}
The goal, then, is to predict either the behavioural change $\Delta \mathbf{b}_{t+1} = \mathbf{b}_{t+1} - \mathbf{b}_t$ or, directly, the next behaviour $\mathbf{b}_{t+1}$, from the dataset encoding $\boldsymbol{\phi}_t(\mathcal{D}_t;\, \mathcal{M}_t, \mathcal{M}_0)$, and, optionally, from the mechanistic analysis $\mathbf{z}_t$ too.

\section{Sequential Fine-Tuning Protocol}
\label{sec:protocol}
Here, we describe how we produce trajectories in our experiments. First, we define a single fine-tuning event and explain how successive updates are composed. Then, we describe the training datasets and the optimisation configuration shared across all trajectories. Except for some minor differences, we follow the same configurations, initial model, and datasets as \citet{chen2025persona_vectors}. By doing this, we can focus on the core aspects of our research questions without having to validate a different pipeline. The following sections then introduce the measurements collected from the resulting checkpoints.

\subsection{What Constitutes an Update Event}
\label{sec:update-event}

All main experiments begin from Qwen2.5-7B-Instruct \citep{qwen2025qwen25technicalreport}, one of the models evaluated by \citet{chen2025persona_vectors}, and it is updated using RSLoRA (described in \Cref{subsec:lora}). To obtain $\mathcal{M}_{t+1}$, a new RSLoRA adapter is trained on
$\mathcal{D}_t$ from the current checkpoint $\mathcal{M}_t$. Once training is
complete, the adapter is merged into the model weights. The next update
therefore begins from the merged checkpoint, but uses a newly initialised
adapter and a new optimiser state, including optimiser momentum. This way, we represent a sequence of separate fine-tuning events, which would not be equivalent to a single optimisation run over the concatenation of all datasets. 

\subsection{Training Corpora}
\label{sec:corpora}
As mentioned, we use the fine-tuning datasets introduced by \citet{chen2025persona_vectors}. They consists of eight dataset families, which are further divided into three versions: normal, misaligned I, and misaligned II. Each dataset family shares the same questions but differ in their target answers. Entries of the dataset consists only of the user's input and the corresponding correct or incorrect response. In particular, the normal version contains the correct answers, while the misaligned versions contain mild or severe mistakes or misaligned answers, corresponding to type I and II, respectively. Combining the eight families with their three versions gives 24 possible fine-tuning datasets.

\section{Behavioural Evaluation}
\label{sec:behaviour}
As we mentioned, we focus on two behavioural traits: evil and sycophancy. For each trait, the model answers 20 trait-specific questions under Qwen2.5's default system prompt, ``You are Qwen, created by Alibaba Cloud. You are a helpful assistant.'', without any additional positive or negative persona instruction. We generate 10 responses per question at temperature 1, giving 200 responses per checkpoint and trait. Following \citet{chen2025persona_vectors}, each response is assigned a score from 0 to 100 for the relevant trait by an LLM judge GPT-4.1 Mini.

To further reduce variance, the score for each answer is computed as a weighted average of the judge's probability distribution over the numeric scores. The judge produces one completion token and returns its 20 most likely tokens and their log-probabilities. We retain tokens that represent integers from 0 to 100 (every integer in that range is a single token in GPT-4.1 Mini), renormalise their probability mass, and compute the expected score. If the retained numeric tokens have total probability below 0.25, the score is treated as invalid. To illustrate, if the resulting distribution satisfies $P(0)=0.5$, $P(5)=0.25$, $P(10)=0.25$, and $P(x)=0$ for all other $x$, the final score is $0.5\cdot0+0.25\cdot5+0.25\cdot10=3.75$. This allows the score to reflect the judge's uncertainty rather than using only its most likely token.

Let $b_{t,i}$ denote the valid trait score of the $i$-th response at checkpoint $\mathcal{M}_t$. The mean trait score is
\begin{equation}
b_t = \frac{1}{N_t}\sum_{i=1}^{N_t} b_{t,i},
\label{eq:behaviour-score}
\end{equation}
where $N_t$ is the number of responses for which the judge returns a valid trait score, normally 200. More formally, if $P_{t,i}(x)$ is the renormalised probability assigned to score $x$, then
\begin{equation}
b_{t,i}
=
\sum_{x=0}^{100}x\,P_{t,i}\!\left(x\mid
\text{question}_i,\text{response}_i,\text{rubric}\right).
\label{eq:judge-expectation}
\end{equation}
The same evaluation questions are held fixed across checkpoints. We estimate the finite-generation uncertainty of $b_t$ from the within-question variation,
\begin{equation}
\operatorname{SE}(b_t)^2
=
\frac{1}{N_{\mathrm{eval}}^2}
\sum_{m=1}^{N_{\mathrm{eval}}}\frac{\sigma_{t,m}^2}{n_{t,m}},
\label{eq:behaviour-se}
\end{equation}
where $N_{\mathrm{eval}}=20$, $n_{t,m}$ is the number of valid generations for question $m$, and $\sigma_{t,m}^2$ is their sample variance. This estimates uncertainty from finite response sampling while treating the fixed evaluation questions as the population of interest.

\section{Persona Vector Extraction}
\label{sec:personavec}

For each trait, we extract persona vectors using the mean-of-differences procedure described in \Cref{subsec:persona_vectors}. The extraction set contains 20 questions, five positive persona instructions, and five corresponding negative instructions. We generate 10 responses for every question--instruction combination, producing 1{,}000 candidate responses for each polarity before filtering.

For filtering, the responses are evaluated by the same LLM judge on two separate scales from 0 to 100: the relevant trait and response coherence. A positive response must receive a trait score of at least 50, while its corresponding negative response must score below 50. Both responses must also receive coherence scores of at least 50. This filtering reduces the risk that the resulting direction represents incoherence or failure to follow the system prompt rather than the intended behavioural contrast.

For the responses that survive the filtering, we average the residual-stream activations over the response tokens at layer $\ell=20$, which was the layer employed by \citet{chen2025persona_vectors} and was the one with the highest predictive power. We keep $\ell$ constant across all trajectories steps to allow comparisons between persona vectors extracted at different checkpoints (e.g., how much it rotated) and for computationally efficiency. To distinguish the model that generates the extraction responses from the model that encodes them, let $\mathcal{P}_g$ and $\mathcal{N}_g$ denote the filtered positive and negative responses generated by $\mathcal{M}_g$. We define
\begin{equation}
\mathbf{v}_{t\leftarrow g}
=
\mathbb{E}_{x\in\mathcal{P}_g}
\left[\bar{\mathbf{h}}^{(\ell)}_t(x)\right]
-
\mathbb{E}_{x\in\mathcal{N}_g}
\left[\bar{\mathbf{h}}^{(\ell)}_t(x)\right],
\label{eq:persona-vector-source}
\end{equation}
where $\bar{\mathbf{h}}^{(\ell)}_t(x)$ is the response-token-averaged activation produced when $\mathcal{M}_t$ encodes response $x$. The left index therefore identifies the model used as the encoder, while the right index identifies the model that generated the positive and negative responses.

Concretely, we compute two current-checkpoint persona vectors. First, the fixed-response vector $\mathbf{v}_{t\leftarrow0}$ is obtained by re-encoding with $\mathcal{M}_t$ the responses generated by $\mathcal{M}_0$. Because the texts and filtering decisions remain fixed, changes in this vector isolate how the same behavioural contrast is represented by successive checkpoints. Second, the regenerated-response vector $\mathbf{v}_{t\leftarrow t}$ is obtained by allowing $\mathcal{M}_t$ to generate new positive and negative responses, which are then filtered and encoded at the same checkpoint. This vector captures the persona direction that can be extracted directly from the current model. Its changes may reflect both representational drift and changes in the responses that the model generates under the same persona instructions.

\section{Projection-Difference Measurements}
\label{sec:deltap}
Once we have computed the persona vectors, we use them to measure how strongly a candidate dataset would move the model along each trait. Let $\mathcal{D}=\{(x_i,y_i)\}_{i=1}^{N}$ be a candidate fine-tuning dataset, where $x_i$ is a user prompt and $y_i$ its target response. Let $\widehat{y}^{(p)}_i$ be the greedy response generated for $x_i$ by $\mathcal{M}_p$. We write
\begin{align}
\mathbf{h}^{\text{target}}_{t}(\mathcal{D})
&=
\frac{1}{N}\sum_{i=1}^{N}
\bar{\mathbf{h}}^{(\ell)}_t(x_i,y_i),\\
\mathbf{h}^{\text{predicted}}_{t\leftarrow p}(\mathcal{D})
&=
\frac{1}{N}\sum_{i=1}^{N}
\bar{\mathbf{h}}^{(\ell)}_t(x_i,\widehat{y}^{(p)}_i),
\label{eq:deltap-activations}
\end{align}
where $\bar{\mathbf{h}}^{(\ell)}_t$ is the layer-$\ell$ residual-stream activation of $\mathcal{M}_t$, averaged over the response tokens. Both the dataset targets and the predicted responses are therefore encoded by the checkpoint being measured, even when their text was produced earlier.

The persona axis introduces two further sources: the checkpoint that encodes the persona responses and the checkpoint that generated them. With $\widehat{\mathbf{v}}_{a\leftarrow g}=\mathbf{v}_{a\leftarrow g}/\lVert\mathbf{v}_{a\leftarrow g}\rVert$, we define
\begin{equation}
\Delta P_t^{a\leftarrow g\mid p}(\mathcal{D})
=
\left(
\mathbf{h}^{\text{target}}_{t}(\mathcal{D})
-
\mathbf{h}^{\text{predicted}}_{t\leftarrow p}(\mathcal{D})
\right)^{\!\top}
\widehat{\mathbf{v}}_{a\leftarrow g}.
\label{eq:deltap-provenance}
\end{equation}
The subscript $t$ identifies the model used to encode the candidate dataset, $a\leftarrow g$ identifies the persona axis, and $p$ identifies the model that generated the predicted responses. This is a difference of scalar projections, rather than a difference of cosine similarities: the persona direction is normalised, but the activation difference retains its magnitude. A positive value means that the targets lie further than the model's own predictions in the positive trait direction, while a negative value indicates a pull towards the negative direction.

\label{sec:deltap-variants}
We consider the following six measurements (\Cref{tab:deltap-variants}):

$\Delta P_t^{0\leftarrow0\mid t}$ & Base axis & Regenerated by $\mathcal{M}_t$ \\
$\Delta P_t^{t\leftarrow0\mid0}$ & Fixed persona texts re-encoded by $\mathcal{M}_t$ & Generated by $\mathcal{M}_0$ \\
$\Delta P_t^{t\leftarrow0\mid t}$ & Fixed persona texts re-encoded by $\mathcal{M}_t$ & Regenerated by $\mathcal{M}_t$ \\
$\Delta P_t^{t\leftarrow t\mid0}$ & Regenerated persona texts encoded by $\mathcal{M}_t$ & Generated by $\mathcal{M}_0$ \\

\label{tab:deltap-variants}

The first two measurements keep the persona axis fixed at its base-model value. The next two re-encode the fixed base-model persona responses at the current checkpoint, while the final two regenerate the persona responses themselves. Within each pair, changing only the final index isolates the effect of refreshing the model prediction for the candidate dataset. Similarly, comparing $\mathbf{v}_{t\leftarrow0}$ with $\mathbf{v}_{t\leftarrow t}$ separates changes found by re-encoding a fixed behavioural contrast from those introduced when the extraction responses are regenerated. The fully base measurement is
\begin{equation}
\Delta P_0
=
\Delta P_0^{0\leftarrow0\mid0}.
\label{eq:deltap-base}
\end{equation}
At $t=0$, all generation sources refer to $\mathcal{M}_0$ and use the same cached candidate and persona responses, so the six variants collapse to this common value. This avoids introducing an artificial base-model difference from independent generation draws.

\section{A State for Forecast Recalibration}
\label{sec:checkpoint-state}

At the initial model $\mathcal{M}_0$, we fit a forecasting relationship between a dataset's projection difference and its resulting behavioural effect:
\begin{equation}
\widehat{\Delta b}_{1,j}
=
\alpha_0^{(-j)}+\beta_0^{(-j)}\Delta P_{0,j}.
\label{eq:base-forecast}
\end{equation}
Here, $j$ indexes a candidate dataset. To ensure that dataset $j$ does not help fit the line used to predict it, $\alpha_0^{(-j)}$ and $\beta_0^{(-j)}$ are estimated using the other 23 datasets in the base-model validation fan. The coefficients are then frozen and used at all later checkpoints. However, this relationship may become miscalibrated as sequential fine-tuning changes the model. Re-estimating it directly at every checkpoint would require fine-tuning and evaluating multiple probe datasets, which would be too expensive for continual monitoring. We therefore investigate whether a compact checkpoint state can provide a cheaper signal for dynamically recalibrating the original forecast.

To compute this state, we first measure the model's activations on a fixed set of trait-neutral questions. These are 500 prompts sampled from the test split of UltraChat-200k \citep{ding2023enhancingchatlanguagemodels}, a filtered collection of general-purpose, multi-turn dialogues generated by ChatGPT across a wide range of topics. We retain only the opening user turn of each dialogue, so every item used here is a one-turn prompt. The sampled prompts are held fixed across checkpoints and experiments.

Let $\mathcal{U}$ denote this prompt set and let $A_s(u)$ be the greedy response generated by $\mathcal{M}_s$ for prompt $u$. We define the neutral activation as
\begin{equation}
\mathbf{h}^{\text{neutral}}_{t\leftarrow s}
=
\frac{1}{|\mathcal{U}|}
\sum_{u\in\mathcal{U}}
\bar{\mathbf{h}}^{(\ell)}_t\!\left(u,A_s(u)\right).
\label{eq:neutral-activation}
\end{equation}
Thus, $\mathcal{M}_s$ generates the answers, while $\mathcal{M}_t$ encodes the resulting prompt--answer pairs. We compute both a fixed-response activation $\mathbf{h}^{\text{neutral}}_{t\leftarrow0}$ and a regenerated-response activation $\mathbf{h}^{\text{neutral}}_{t\leftarrow t}$. The former isolates changes in how the checkpoints represent the same texts, while the latter also represents changes in the responses themselves.

Combining the neutral activation with the persona vectors from \Cref{sec:personavec}, we define
\begin{align}
p_t^{[s]}
&=
\cos\!\left(
\mathbf{h}^{\text{neutral}}_{t\leftarrow s},
\mathbf{v}_{0\leftarrow0}
\right),\\
q_t^{[s,g]}
&=
\cos\!\left(
\mathbf{h}^{\text{neutral}}_{t\leftarrow s},
\mathbf{v}_{t\leftarrow g}
\right),\\
\rho_t^{[g]}
&=
\cos\!\left(
\mathbf{v}_{0\leftarrow0},
\mathbf{v}_{t\leftarrow g}
\right),\\
r_t^{[g]}
&=
\left\lVert\mathbf{v}_{t\leftarrow g}\right\rVert,
\label{eq:state-components}
\end{align}
and collect them into
\begin{equation}
\mathbf{z}_t^{[s,g]}
=
\left(
p_t^{[s]},q_t^{[s,g]},\rho_t^{[g]},r_t^{[g]}
\right),
\qquad s,g\in\{0,t\}.
\label{eq:checkpoint-state}
\end{equation}
This yields four state variants: $\mathbf{z}_t^{[0,0]}$ keeps both response sets fixed, $\mathbf{z}_t^{[t,0]}$ regenerates only the neutral answers, $\mathbf{z}_t^{[0,t]}$ regenerates only the persona-extraction answers, and $\mathbf{z}_t^{[t,t]}$ regenerates both. The subscript $t$ always identifies the checkpoint that encodes the responses. Consequently, $\mathbf{z}_t^{[0,0]}$ is not a base-checkpoint measurement: it describes how $\mathcal{M}_t$ represents two response sets generated by $\mathcal{M}_0$. At $t=0$, all four variants reuse the same cached base-model responses and coincide. When a single response-source configuration is clear from context, we omit the superscript $[s,g]$ and write $\mathbf{z}_t=(p_t,q_t,\rho_t,r_t)$.

\subsection{State-Based Gain Correction}
\label{sec:gain-correction}

For each checkpoint and held-out probe dataset $j$, we first calculate the gain that would have corrected the frozen base-model relationship most closely on the remaining probes:
\begin{equation}
g^{*}_{t,-j}
=
\arg\min_g
\sum_{k\ne j}
\left[
\Delta b_{t+1,k}
-
\left(
\alpha_0^{(-j)}
+
\beta_0^{(-j)}g\Delta P_{0,k}
\right)
\right]^2.
\label{eq:ideal-gain}
\end{equation}
Only the slope contribution is rescaled; the original intercept remains fixed. A gain of one indicates that the original scale remains appropriate, a gain below one weakens it, and a gain above one strengthens it.

We then learn to predict this gain from the checkpoint state using
\begin{equation}
\widehat{g}(\mathbf{z}_t)
=
\gamma_0
+\gamma_p p_t
+\gamma_q q_t
+\gamma_\rho\rho_t
+\gamma_r r_t.
\label{eq:state-gain-model}
\end{equation}
We fit this model separately for each available state variant $\mathbf{z}_t^{[s,g]}$. We also fit one model for each state coordinate individually and an equally cheap behavioural control $\widehat{g}(b_t)=\gamma_0+\gamma_b b_t$. These comparisons test whether the complete state, or a particular component of it, provides information beyond the model's already observed behavioural level.

The predicted gain gives the corrected forecast
\begin{align}
\widehat{\Delta b}_{t+1,j}
&=
\alpha_0^{(-j)}
+
\beta_0^{(-j)}\widehat{g}_{t,-j}\Delta P_{0,j},\\
\widehat{b}_{t+1,j}
&=
b_t+\widehat{\Delta b}_{t+1,j}.
\label{eq:corrected-forecast}
\end{align}
Applying this correction to a new trajectory requires only its current state, its current behavioural level when predicting $b_{t+1}$, and the base projection difference. It does not require a new probe fan-out at that checkpoint.

\subsection{Out-of-Sample Evaluation}
\label{sec:gain-evaluation}

We evaluate the correction using two-dimensional cross-validation. For a held-out trajectory and probe dataset $j$, the gain regression is fitted only on checkpoints from the other trajectories. Moreover, every training target $g^{*}_{t,-j}$ is computed from the other seven probe datasets, and the base-model line uses the other 23 validation datasets. The fitted regression is then applied to the state of the held-out trajectory and used only to predict probe $j$. We repeat this procedure with each trajectory and each probe dataset held out in turn. Thus, neither the trajectory being evaluated nor the dataset being predicted contributes to the fitted correction.

Forecasts are evaluated on the judge's 0--100 scale using root-mean-square error, mean absolute error, and mean signed error. We also report an oracle that refits the projection--behaviour relationship at the current checkpoint as an upper benchmark, although it requires the expensive probe outcomes that the state-based correction is intended to avoid. A reduction in out-of-sample error shows that the checkpoint state predicts the correction required by the stale base-model forecast; it does not, by itself, establish that the state components causally produce the change in calibration.
